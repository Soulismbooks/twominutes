# Admin Portal full feature implementation plan

## Goal
Make the private Admin Portal convenient from a phone for writing posts with structured blocks, image uploads, SEO fields, preview, drafts and safe review/publishing.

## Existing facts
- The public site is generated by `feed.atom -> build.py -> public/ -> main Worker`.
- Admin data is stored in a separate D1 database.
- Admin UI assets are embedded in `admin-ui/src/index.js` as generated strings copied from `admin-ui/public/`.
- Cloudflare API check on 2026-10-20 returned R2 error 10042: “Please enable R2 through the Cloudflare Dashboard.” Until R2 is activated and a bucket is created, real image uploads cannot be enabled.
- Public Worker `twominutes`, root DNS and www DNS must not be altered by Admin work.

## Feature set in scope
1. Responsive block editor: heading, paragraph, unordered/ordered list, quote, divider, image block; keyboard/mobile friendly toolbar and plain-text/source fallback.
2. Image manager: Gallery file picker, preview, alt text, caption, featured image. Actual upload requires R2 bucket binding to the dedicated Admin API Worker. Enforce signed Cloudflare Access identity, image MIME allowlist, file-size limit, random object keys, no public bucket listing and safe content headers.
3. Post metadata: slug, summary/excerpt, SEO title, SEO description, canonical URL, category, labels/tags, author, publication date and featured image fields.
4. Preview: article content styled independently of the Admin UI in an isolated iframe; responsive preview sizes.
5. Draft workflows: autosave, edit, duplicate-slug handling, search, unsaved warning, draft statuses.
6. Publishing: a deliberate “Submit for review” action, a GitHub PR/diff/validation step, then an explicit admin approval before generated public content can change. The workflow must preserve the existing feed/build/Worker deployment architecture and must never publish from an untrusted or arbitrary browser HTML payload.
7. Analytics only if a real Cloudflare/Web Analytics source is configured; do not display fake metrics.

## Migration notes
New optional metadata columns should be added with a new idempotent migration. Never rewrite migration 0001 or point to public site's DB.

## Deployment/acceptance gates
- Unit tests for API schema validation, JWT/origin, metadata limits, safe upload content types and publishing status transitions.
- UI/Worker embedded asset-sync check and JS syntax tests.
- D1 schema/row-count verification and draft save/reload test.
- R2 activation/bucket provisioning and authenticated image upload/read test.
- Browser acceptance test on admin.twominutes.in.
- Public site's existing root/www DNS and `twominutes` Worker remain untouched.
- Keep this PR unmerged until the interactive test passes and the changes have been reviewed.
